= Provisionnez des partages de fichiers CIFS et NFS à l'aide des API d'Active IQ Unified Manager
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Vous pouvez provisionner des partages CIFS et des partages de fichiers NFS sur vos Storage Virtual Machines (SVM) à l’aide des API de provisionnement fournies dans le cadre d’Active IQ Unified Manager. Ce workflow de provisionnement décrit en détail les étapes permettant de récupérer les clés des SVM, des Performance Service Levels et des Storage Efficiency Policies avant de créer les partages de fichiers.

Le diagramme suivant illustre chaque étape d’un processus de provisionnement de partage de fichiers. Il inclut le provisionnement des partages CIFS et des partages de fichiers NFS.

image::../media/create_fileshares.gif[Un diagramme illustrant le flux de travail de provisionnement des partages de fichiers CIFS et NFS, de la configuration du SVM à la création du partage]

[NOTE]
====
Assurez-vous de ce qui suit :

* Les clusters ONTAP ont été ajoutés à Unified Manager et la clé du cluster a été obtenue.
* Des SVM ont été créés sur les clusters.
* Les SVM prennent en charge les services CIFS et NFS. Le provisionnement des partages de fichiers peut échouer si les SVM ne prennent pas en charge les services requis.
* Le port FCP est en ligne pour le provisionnement des ports.


====
. Déterminez si des LIF de données ou des points de terminaison d'accès sont disponibles sur la SVM sur laquelle vous souhaitez créer le partage CIFS. Obtenez la liste des points de terminaison d'accès disponibles sur la SVM :
+
[cols="3*"]
|===
| Catégorie | Verbe HTTP | Chemin 


 a| 
fournisseur de stockage
 a| 
GET
 a| 
`/storage-provider/access-endpoints`
`/storage-provider/access-endpoints/\{key}`

|===
+
*Exemple de cURL*

+
[listing]
----
curl -X GET "https://<hostname>/api/storage-provider/access-endpoints?resource.key=7d5a59b3-953a-11e8-8857-00a098dcc959" -H "accept: application/json" -H "Authorization: Basic <Base64EncodedCredentials>"
----
. Si votre point de terminaison d'accès figure dans la liste, obtenez la clé du point de terminaison d'accès, sinon créez le point de terminaison d'accès.
+
[NOTE]
====
Veillez à créer des points d'accès sur lesquels le protocole CIFS est activé. Le provisionnement des partages CIFS échoue si vous n'avez pas créé de point d'accès avec le protocole CIFS activé.

====
+
[cols="3*"]
|===
| Catégorie | Verbe HTTP | Chemin 


 a| 
fournisseur de stockage
 a| 
POST
 a| 
`/storage-provider/access-endpoints`

|===
+
*Exemple de cURL*

+
Vous devez saisir, en tant que paramètres d'entrée, les détails du point de terminaison d'accès que vous souhaitez créer.

+
[listing]
----

\"ip\": { \"address\": \"10.162.83.26\",

\"netmask\": \"255.255.0.0\" },
\"lun\": { \"key\": \"cbd1757b-0580-11e8-bd9d-00a098d39e12:type=lun,uuid=d208cc7d-80a3-4755-93d4-5db2c38f55a6\" },

----
+
La sortie JSON affiche une clé d'objet Job que vous pouvez utiliser pour vérifier le point de terminaison d'accès que vous avez créé.

. Vérifiez le point de terminaison d'accès :
+
[cols="3*"]
|===
| Catégorie | Verbe HTTP | Chemin 


 a| 
serveur de gestion
 a| 
GET
 a| 
`/management-server/jobs/\{key}`

|===
. Déterminez si vous devez créer un partage CIFS ou un partage de fichiers NFS. Pour créer un partage CIFS, suivez les étapes suivantes :
+
.. Déterminez si le serveur CIFS est configuré sur votre SVM, c'est-à-dire si un mappage Active Directory est créé sur le SVM.
+
[cols="3*"]
|===
| Catégorie | Verbe HTTP | Chemin 


 a| 
fournisseur de stockage
 a| 
GET
 a| 
`/storage-provider/active-directories-mappings`

|===
.. Si le mappage Active Directory est créé, prenez la clé, sinon, créez le mappage Active Directory sur la SVM.
+
[cols="3*"]
|===
| Catégorie | Verbe HTTP | Chemin 


 a| 
fournisseur de stockage
 a| 
POST
 a| 
`/storage-provider/active-directories-mappings`

|===
+
*Exemple de cURL*

+
Vous devez saisir les détails nécessaires à la création du mappage Active Directory, en tant que paramètres d'entrée.

+
[listing]
----
curl -X POST "https://<hostname>/api/storage-provider/active-directories-mappings" -H "accept: application/json" -H "Content-Type: application/json" -H "Authorization: Basic <Base64EncodedCredentials>"
{ \"_links\": {},
\"dns\": \"10.000.000.000\",
\"domain\": \"example.com\",
\"password\": \"string\",
\"svm\": { \"key\": \"9f4ddea-e395-11e9-b660-005056a71be9:type=vserver,uuid=191a554a-f0ce-11e9-b660-005056a71be9\" },
\"username\": \"string\"}"
----
+
Il s'agit d'un appel synchrone et vous pouvez vérifier la création du mappage Active Directory dans le résultat. En cas d'erreur, le message d'erreur s'affiche afin de vous permettre de résoudre le problème et de relancer la requête.



. Obtenez la clé SVM de la SVM sur laquelle vous souhaitez créer le partage CIFS ou le partage de fichiers NFS, comme décrit dans la rubrique du flux de travail _Vérification des SVM sur les clusters_.
. Obtenez la clé du Performance Service Level en exécutant l'API suivante et en récupérant la clé dans la réponse.
+
[cols="3*"]
|===
| Catégorie | Verbe HTTP | Chemin 


 a| 
fournisseur de stockage
 a| 
GET
 a| 
`/storage-provider/performance-service-levels`

|===
+
[NOTE]
====
Vous pouvez récupérer les détails des niveaux de service de performance définis par le système en définissant le paramètre d'entrée `system_defined` sur `true`. À partir de la sortie, obtenez la clé du niveau de service de performance que vous souhaitez appliquer au partage de fichiers.

====
. Si vous le souhaitez, obtenez la clé de la stratégie d'efficacité du stockage que vous souhaitez appliquer au partage de fichiers en exécutant l'API suivante et en récupérant la clé dans la réponse.
+
[cols="3*"]
|===
| Catégorie | Verbe HTTP | Chemin 


 a| 
fournisseur de stockage
 a| 
GET
 a| 
`/storage-provider/storage-efficiency-policies`

|===
. Créez le partage de fichiers. Vous pouvez créer un partage de fichiers qui prend en charge à la fois CIFS et NFS en spécifiant la liste de contrôle d'accès et les règles d'export. Les sous-étapes suivantes fournissent des informations si vous souhaitez créer un partage de fichiers pour prendre en charge un seul des protocoles sur le volume. Vous pouvez également mettre à jour un partage de fichiers NFS pour inclure la liste de contrôle d'accès après avoir créé le partage NFS. Pour plus d'informations, consultez la rubrique _Modifying storage workloads_.
+
.. Pour créer uniquement un partage CIFS, rassemblez les informations relatives à la liste de contrôle d'accès (ACL). Pour créer le partage CIFS, fournissez des valeurs valides pour les paramètres d'entrée suivants. Pour chaque groupe d'utilisateurs que vous attribuez, une ACL est créée lorsqu'un partage CIFS/SMB est provisionné. Selon les valeurs que vous saisissez pour l'ACL et le mappage Active Directory, le contrôle d'accès et le mappage sont déterminés pour le partage CIFS lors de sa création.
+
*Une commande cURL avec des valeurs d'exemple*

+
[listing]
----
{
  "access_control": {
    "acl": [
      {
        "permission": "read",
        "user_or_group": "everyone"
      }
    ],
    "active_directory_mapping": {
      "key": "3b648c1b-d965-03b7-20da-61b791a6263c"
    },
----
.. Pour créer uniquement un partage de fichiers NFS, rassemblez les informations relatives aux règles d'export. Pour créer le partage de fichiers NFS, veuillez fournir des valeurs valides pour les paramètres d'entrée suivants. En fonction des valeurs que vous fournissez, les règles d'export sont associées au partage de fichiers NFS lors de sa création.
+
[NOTE]
====
Lors du provisionnement du partage NFS, vous pouvez soit créer des règles d'export en fournissant toutes les valeurs requises, soit fournir la clé des règles d'export et réutiliser des règles d'export existantes. Si vous souhaitez réutiliser des règles d'export pour la machine virtuelle de stockage, vous devez ajouter la clé des règles d'export. Si vous ne connaissez pas cette clé, vous pouvez récupérer la clé des règles d'export à l'aide de l' `/datacenter/protocols/nfs/export-policies`API. Pour créer de nouvelles règles, vous devez saisir les règles comme indiqué dans l'exemple suivant. Pour les règles saisies, l'API tente de rechercher des règles d'export existantes en faisant correspondre l'hôte, la machine virtuelle de stockage et les règles. S'il existe des règles d'export, elles sont utilisées. Sinon, de nouvelles règles d'export sont créées.

====
+
*Une commande cURL avec des valeurs d'exemple*

+
[listing]
----
"export_policy": {
      "key": "7d5a59b3-953a-11e8-8857-00a098dcc959:type=export_policy,uuid=1460288880641",
      "name_tag": "ExportPolicyNameTag",
      "rules": [
        {
          "clients": [
            {
              "match": "0.0.0.0/0"
            }
----


+
